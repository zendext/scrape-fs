# First-Version Use Cases

> This is an English translation. If the English and Chinese documents conflict, the Chinese documentation is authoritative.

This document describes the main first-version workflows from an actor-goal perspective. Data structures, error codes, and transaction semantics are defined by the linked specifications.

## 1. Actors

| Actor | Description |
| --- | --- |
| Administrator | Manages Libraries, the daemon, and system configuration |
| Control user | Creates Projections, validates/applies batches, and confirms or undoes results |
| External Agent skill | Identifies media with the caller's permissions, generates batches, and invokes the CLI |
| Media player | Reads ProjectionFiles and creates or modifies OverlayFiles through FUSE |
| Daemon | Performs validation, persistence, FUSE operations, and recovery |

## UC-01 Create a Library

### Actor

Administrator

### Goal

Create a virtual media Library using a selected Profile.

### Preconditions

- The daemon is ready.
- No ACTIVE Library uses the requested name.
- The Profile is built in and available.

### Trigger

```bash
scrapefs library add jellyfin --profile jellyfin@1
```

### Main Flow

1. The CLI submits the name and Profile.
2. The daemon validates both values.
3. One transaction creates the LibraryRoot and Library record.
4. The daemon logs the operation and increments namespace version.
5. `/mnt/scrapefs/jellyfin` appears through FUSE.

### Alternative Flows

- Name already exists: return `EEXIST`.
- Profile is unavailable: return `ProfileNotFound`.
- Transaction fails: leave no LibraryRoot.

### Result

The Library is ACTIVE and can receive direct Projections and Projection batches.

- [Architecture](architecture.md)
- [Operations and CLI](operations.md)

## UC-02 Create One Projection Manually

### Actor

Control user

### Goal

Map an existing media file into a Library without modifying the source.

### Preconditions

- The daemon is ready.
- The target Library is ACTIVE.
- The caller has control permission.
- The daemon can read the source file.
- The target path is free.

### Trigger

```bash
scrapefs projection add \
  /mnt/disk1/downloads/Dune.mkv \
  "jellyfin:/Movies/Dune (2021)/Dune (2021).mkv"
```

### Main Flow

1. The daemon safely opens the source.
2. It confirms a regular file.
3. It records source path, identity, and cached attributes.
4. It validates the Library target path.
5. One transaction creates missing directories and the ProjectionFile.
6. The daemon logs the operation and increments namespace version.
7. The virtual path becomes visible and readable.

### Alternative Flows

- Source is missing: return `ENOENT`.
- Source path contains a symbolic link: reject it.
- Target exists: return `EEXIST`.
- Library is missing: return `LibraryNotFound`.
- Transaction fails: leave no partial directory or ProjectionFile.

### Result

The ProjectionFile is readable and read-only. The source file is unchanged.

### Related Specifications

- [Projection model](projection.md)
- [Filesystem and object storage](filesystem.md)

## UC-03 Validate a Projection Batch Generated by an External Agent

### Actors

Control user, external Agent skill

### Goal

Identify an arbitrarily named movie directory and preview a Projection batch without changing the namespace.

### Preconditions

- The daemon is ready.
- The target Library is ACTIVE.
- The external Agent can read the source directory with the caller's permissions.
- The daemon service account can read the sources explicitly listed by the batch.

### Trigger

```bash
scrapefs projection batch validate --file /tmp/dune.batch.json --json
```

### Main Flow

1. The external Agent enumerates the source directory and uses its own `ffprobe` and metadata tools.
2. It resolves media-identification ambiguity and generates `scrapefs.projection-batch/v1` JSON.
3. The daemon strictly parses the batch and safely opens every source.
4. It runs generic path, Profile, and conflict validation.
5. It returns the diff, warnings, digest, and namespace version.
6. It closes every source fd and writes nothing to SQLite.

### Alternative Flows

- Invalid schema, permission, or source type: validation fails.
- A source changes during validation: return `ESTALE`.
- An unsafe or conflicting target: return a blocking error.

### Result

The external Agent receives review output and a digest. The FUSE namespace and database are unchanged.

### Related Specifications

- [Projection batches and the external Agent workflow](scrape.md)
- [Projection model](projection.md)

## UC-04 Correct an Invalid Batch

### Actors

Control user, external Agent skill

### Goal

Resolve media-identification, target, or conflict problems externally and validate the batch again.

### Preconditions

- The previous validation returned a blocking error or the user requested a change.
- The external Agent retains the original batch JSON.

### Trigger

```bash
scrapefs projection batch validate --file corrected.batch.json --json
```

### Main Flow

1. The external Agent changes its batch file.
2. The daemon treats the changed file as a new stateless request.
3. It reruns every source, path, Profile, and conflict check.
4. It returns a new digest and diff.

### Result

The daemon stores no old version or revision. The external Agent owns comparison and change history.

### Related Specifications

- [Projection batches and the external Agent workflow](scrape.md)

## UC-05 Apply a Projection Batch Atomically

### Actor

Control user

### Goal

Atomically publish the batch the user just confirmed.

### Preconditions

- The CLI displayed validation output.
- The caller confirmed apply.
- The caller has the validation digest.
- The Library is ACTIVE.

### Trigger

```bash
scrapefs projection batch apply \
  --file /tmp/dune.batch.json \
  --expected-digest sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef
```

### Main Flow

1. The daemon parses the batch again and checks the expected digest.
2. It obtains the confirming UID/GID from Unix peer credentials.
3. It safely reopens and validates every source.
4. It rechecks paths, Profile rules, and conflicts.
5. One SQLite transaction creates applied-batch provenance, Directories, and ProjectionFiles.
6. It writes one batch operation-log entry.
7. It increments namespace version and commits.
8. It updates the in-memory index and invalidates FUSE caches.
9. The CLI returns a stable batch ID.

### Alternative Flows

- Digest mismatch: reject and require validation again.
- Source changed: return `ESTALE`.
- Target conflicts: return `EEXIST`.
- Transaction fails: leave no provenance, directory, or Projection.

### Result

Every Projection is published together. Source files remain unchanged.

### Related Specifications

- [Projection batches and the external Agent workflow](scrape.md)
- [Architecture](architecture.md)

## UC-06 Create Media Artifacts through FUSE

### Actor

External Agent skill

### Goal

Create NFO files, artwork, and other OverlayFiles after batch apply.

### Preconditions

- The batch is applied.
- The external Agent has FUSE write permission on the target directory.

### Trigger

```bash
cp poster.jpg \
  "/mnt/scrapefs/jellyfin/Movies/Dune (2021) [tmdbid-438631]/poster.jpg"
```

### Main Flow

1. The external Agent uses ordinary FUSE create, write, and rename operations.
2. The OverlayFile uses FUSE caller UID/GID and ordinary mode.
3. The backing object uses daemon-private permissions.

### Result

The artifact is visible. ScrapeFS does not record whether a person, script, or Agent created it.

### Related Specifications

- [Filesystem and object storage](filesystem.md)
- [Projection batches and the external Agent workflow](scrape.md)

## UC-07 Undo a Projection Batch

### Actor

Control user

### Goal

Remove Projections created by one batch while retaining sources and OverlayFiles.

### Preconditions

- The batch is applied.

### Trigger

```bash
scrapefs projection batch undo batch-42
```

### Main Flow

1. One transaction removes ProjectionFiles whose legacy `origin_scrape_id` references the batch.
2. It removes empty managed directories.
3. It writes the operation log.
4. It marks the batch undone and stores caller UID/GID.
5. It increments namespace version and commits.
6. The CLI lists OverlayFiles that remain or prevent directory pruning.

### Alternative Flows

- A Projection was already removed: treat it as absent.
- A directory still contains OverlayFiles or other Projections: retain it.
- The batch is already undone: return `AlreadyUndone`.

### Result

Batch Projections disappear. Source files and OverlayFiles remain.

### Related Specifications

- [Projection batches and the external Agent workflow](scrape.md)

## UC-08 Rename or Remove a Projection

### Actors

Control user or a FUSE user with permission

### Goal

Modify the virtual namespace without modifying the source.

### Preconditions

- ProjectionFile exists.
- Target remains in the same Library.
- Caller has permission.

### Trigger

```bash
scrapefs projection mv \
  "jellyfin:/Movies/Dune/Dune.mkv" \
  "jellyfin:/Movies/Dune/Dune (2021).mkv"

scrapefs projection rm \
  "jellyfin:/Movies/Dune/Dune (2021).mkv"
```

### Main Flow

1. The daemon validates the source node and target path.
2. One transaction moves or removes the virtual node.
3. It writes the operation log and increments namespace version.
4. After removal, it cleans empty managed directories.

### Alternative Flows

- Cross-Library rename: return `EXDEV`.
- Target exists: return `EEXIST`.
- Directory still contains content: retain it.

### Result

The virtual path changes or disappears. The source file remains unchanged.

### Related Specifications

- [Projection model](projection.md)

## UC-09 Atomically Update an OverlayFile

### Actor

Media player

### Goal

Safely update NFO, artwork, or subtitles through a temporary-file replacement pattern.

### Preconditions

- Library is mounted.
- Player has write permission.
- Target is not a ProjectionFile.

### Trigger

```text
create movie.nfo.tmp
write
fsync
rename movie.nfo.tmp -> movie.nfo
```

### Main Flow

1. ScrapeFS creates an object in staging.
2. The object safely enters live.
3. SQLite creates the OverlayFile node.
4. The player writes and fsyncs.
5. OverlayFile atomically replaces an existing OverlayFile.
6. The old object is reclaimed after commit.

### Alternative Flows

- Target is ProjectionFile: return `EEXIST`.
- Backing write partially succeeds: retain the written bytes and return the actual length.
- Fsync fails: propagate the backing error.
- Object is missing: return `EIO`.

### Result

The player reads complete new content from the target path. Source files are unaffected.

### Related Specifications

- [Filesystem and object storage](filesystem.md)

## UC-10 Handle a Missing or Replaced Source

### Actors

Media player, control user

### Goal

Keep the namespace inspectable while preventing silent reads from the wrong file.

### Preconditions

- ProjectionFile exists.

### Trigger

The source is externally removed, moved, or replaced at the same path.

### Main Flow

1. lookup/getattr uses cached attributes and keeps the Projection visible.
2. open safely resolves the source and checks identity.
3. Missing source returns `ENOENT`.
4. Identity mismatch returns `ESTALE`.
5. doctor reports a broken or stale Projection.

### Result

ScrapeFS does not automatically remove the Projection and does not silently project a replacement file.

### Related Specifications

- [Projection model](projection.md)

## UC-11 Rebind a Projection to a New Source

### Actor

Control user

### Goal

Bind an existing virtual path to a legitimately moved or replaced source.

### Preconditions

- ProjectionFile exists.
- The new source can be safely read.

### Trigger

```bash
scrapefs projection rebind \
  "jellyfin:/Movies/Dune (2021)/Dune (2021).mkv" \
  --source /mnt/new-disk/Dune.mkv
```

### Main Flow

1. The daemon safely opens the new source.
2. The CLI returns old and new paths and identities plus a confirmation digest.
3. The user explicitly confirms by repeating the command with `--confirm <digest>`.
4. The daemon reopens the source and rejects any changed Projection or source.
5. The daemon updates source path, identity, and cached attributes.
6. It updates virtual ctime, writes the log, and invalidates attributes.
7. New opens read from the new source.

### Alternative Flows

- New source is missing: return `ENOENT`.
- New source path contains a symbolic link: reject it.
- The confirmation is omitted: return the preview without modifying the Projection.
- The confirmation is stale: return `ConfirmationMismatch` without modifying the Projection.

### Result

The virtual path and inode remain stable while content comes from the new source.

### Related Specifications

- [Projection model](projection.md)

## UC-12 Remove a Library

### Actor

Administrator

### Goal

Remove an unused virtual media Library without deleting source files.

### Preconditions

- The daemon is ready.

### Trigger

```bash
scrapefs library remove jellyfin
scrapefs library remove jellyfin --recursive
```

### Main Flow

For an empty Library:

1. Remove LibraryRoot.
2. Mark Library RETIRED.
3. Write the operation log and increment namespace version.

For explicit recursive removal:

1. The administrator waits for in-flight namespace writes.
2. One transaction removes the Library node tree.
3. It clears `root_node_id` and marks Library RETIRED.
4. Overlay objects are reclaimed after commit.

### Alternative Flows

- Ordinary removal of a non-empty Library returns `NotEmpty` (`ENOTEMPTY` in the namespace/FUSE domain).
- An in-flight namespace write causes recursive removal to return `NamespaceWriteInProgress`.

### Result

The Library disappears from the FUSE root and the command returns its RETIRED snapshot. Source files and Projection Batch history remain. Already open Overlay handles remain usable until closed.

### Related Specifications

- [Operations and CLI](operations.md)
- [Architecture](architecture.md)

## UC-13 Recover after Daemon Restart

### Actors

Administrator, systemd

### Goal

Restore virtual Libraries after a normal restart or crash.

### Preconditions

- SQLite and the object store remain available.

### Trigger

`scrapefsd` starts.

### Main Flow

1. Acquire the host-filesystem daemon lock for the ScrapeFS runtime.
2. Open SQLite and validate PRAGMAs.
3. Run migrations.
4. Recover object-store state.
5. Rebuild namespace and inode indexes from SQLite.
6. Clean a stale mount proven to belong to a dead instance.
7. Mount FUSE and create the control socket.
8. Signal readiness.

### Alternative Flows

- The daemon lock is unavailable: exit before opening SQLite.
- Migration fails: do not mount or signal readiness.
- Object is missing: retain the node and let doctor report it.
- Unknown FUSE mount exists: do not unmount it.

### Result

Committed Libraries, Projections, and OverlayFiles become visible again.

### Related Specifications

- [Operations and CLI](operations.md)
- [Filesystem and object storage](filesystem.md)

## UC-14 Diagnose Problems with Doctor

### Actors

Control user, administrator

### Goal

Find persistent or source-file problems that ScrapeFS does not repair automatically.

### Preconditions

- The daemon is ready, or doctor supports a read-only offline mode.

### Trigger

```bash
scrapefs doctor
```

### Main Flow

1. Check Projection source paths and identities.
2. Check that each OverlayFile has its live object.
3. Check for orphan objects with no node reference.
4. Check Library and namespace-tree constraints.
5. Output structured findings and suggested actions.

### Example Findings

```text
BROKEN_PROJECTION
STALE_PROJECTION
MISSING_OBJECT
ORPHAN_OBJECT
INVALID_NAMESPACE
```

### Result

Doctor does not modify source files or the namespace by default. Repairs require an explicit user operation.
